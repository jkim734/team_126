웹 배포 안내

이 문서는 코드를 수정하지 않고 완성된 웹사이트를 공개 주소로 올리는 방법입니다.
예시는 Render를 사용합니다. 현재 버전에는 DB가 필요하지 않습니다.

가장 먼저 알아둘 것

- `127.0.0.1:8013`은 개발자 본인 컴퓨터에서만 열리는 시험 주소입니다.
- 배포가 끝나면 `https://서비스이름.onrender.com` 형태의 공개 주소가 생깁니다.
- 일반 이용자는 Python이나 별도 프로그램을 설치하지 않고 공개 주소만 열면 됩니다.
- 공공데이터 인증키는 GitHub나 코드 파일에 적지 않습니다.
- 환경변수는 인증키를 서버 설정 화면에 비공개로 저장하는 칸입니다.

준비물

1. 전달받은 `신인류126_웹최종본` 폴더
2. GitHub 계정
3. Render 계정
4. 공공데이터포털 일반 인증키

공공데이터 인증키 발급 방법

가능하면 배포 담당자 본인의 공공데이터포털 계정으로 발급받습니다. 아래 3개 데이터에
각각 활용신청해야 웹의 수거함과 대형폐기물 수수료 기능을 모두 사용할 수 있습니다.

1. 공공데이터포털 https://www.data.go.kr 에 접속해 회원가입하고 로그인합니다.
2. 아래 주소를 하나씩 열고 각 페이지의 `활용신청`을 누릅니다.

- 전국폐의약품수거함표준데이터
  https://www.data.go.kr/data/15129445/standard.do
- 전국폐형광등폐건전지수거함표준데이터
  https://www.data.go.kr/data/15155673/standard.do
- 전국대형폐기물수거수수료정보표준데이터
  https://www.data.go.kr/data/15114146/standard.do

3. 신청 구분은 개발계정으로 선택합니다.
4. 활용 목적에는 `지역별 폐기물 배출 정보와 수거함·수수료를 안내하는 웹서비스 개발 및 배포`처럼 작성합니다.
5. 세 데이터의 활용신청을 모두 완료합니다.
6. 공공데이터포털의 `마이페이지 → 데이터 활용 → OpenAPI → 개발계정` 또는
   `인증키 발급현황`에서 신청 상태를 확인합니다. 포털 메뉴 이름은 개편에 따라 조금
   다르게 보일 수 있습니다.
7. 승인된 항목에서 긴 문자열 형태의 `일반 인증키`를 확인합니다.
8. Encoding과 Decoding 키가 둘 다 보이면 `일반 인증키(Decoding)`를 우선 복사합니다.
9. 같은 계정에서 발급된 일반 인증키 하나를 이 웹서비스의 `DATA_GO_KR_API_KEY`에 사용합니다.

신청 직후에는 승인 상태여도 인증 시스템 반영까지 시간이 걸릴 수 있습니다. 인증 오류가
나면 키 철자와 세 데이터의 활용신청 상태를 확인하고 잠시 뒤 다시 시도합니다.

인증키 확인 방법

전달 파일의 `API_연결테스트.py`를 실행하면 키를 파일에 저장하지 않고 세 API 연결을
확인할 수 있습니다.

1. PowerShell에서 전달 폴더로 이동합니다.
2. 아래 명령을 실행합니다.

`py -3.13 API_연결테스트.py`

3. `일반 인증키(Decoding)를 붙여넣고 Enter`가 나오면 키를 붙여넣습니다.
4. 입력 문자가 화면에 보이지 않는 것은 정상입니다.
5. 아래 세 줄이 모두 `연결 성공`인지 확인합니다.

- 폐의약품 수거함
- 폐건전지·폐형광등 수거함
- 대형폐기물 수수료

인증키 실제 값은 TXT, ZIP, GitHub, 단체 채팅, 화면 캡처에 넣지 않습니다. 다른 팀원의
키를 꼭 사용해야 한다면 1:1 보안 채널로 별도 전달받고, 배포 서버 환경변수에만 등록합니다.

1단계: GitHub 저장소 만들기

1. GitHub에 로그인합니다.
2. 오른쪽 위 `+`를 누르고 `New repository`를 선택합니다.
3. Repository name에 `everyday-waste-guide`처럼 영문 이름을 입력합니다.
4. 공개 여부는 팀 방침에 따라 Public 또는 Private을 선택합니다.
5. `Create repository`를 누릅니다.
6. 저장소 화면에서 `uploading an existing file` 또는 `Add file → Upload files`를 누릅니다.
7. 전달 폴더 안의 파일과 폴더를 모두 업로드합니다.
8. `templates`와 `static` 폴더가 반드시 폴더 형태로 함께 올라갔는지 확인합니다.
9. 아래쪽 `Commit changes`를 누릅니다.

GitHub 최상단에서 다음 파일이 바로 보여야 합니다.

- `web_app.py`
- `waste_api.py`
- `requirements-web.txt`
- `render.yaml`
- `templates` 폴더
- `static` 폴더

`.venv`, `.venv313`, `__pycache__`, 의견 PNG, 인증키 파일은 올리지 않습니다.

2단계: Render에 연결하기

1. Render에 로그인합니다.
2. `New +`를 누르고 `Web Service`를 선택합니다.
3. Git Provider에서 GitHub를 연결합니다.
4. 방금 만든 `everyday-waste-guide` 저장소 옆 `Connect`를 누릅니다.
5. 아래처럼 입력합니다.

| 설정 항목 | 입력값 |
|---|---|
| Name | 원하는 영문 서비스 이름 |
| Language/Runtime | Python 3 |
| Branch | main |
| Root Directory | 비워 둠 |
| Build Command | `pip install -r requirements-web.txt` |
| Start Command | `gunicorn web_app:app` |

무료 과제 시연용이면 Instance Type에서 Free를 선택할 수 있습니다. 무료 서버는 오랫동안
접속이 없으면 잠들 수 있어 첫 접속에 시간이 걸릴 수 있습니다.

3단계: 인증키 환경변수 넣기

서비스를 만들기 전에 Environment Variables 영역을 찾습니다.

1. `Add Environment Variable`을 누릅니다.
2. Key에 아래 이름을 정확히 입력합니다.


DATA_GO_KR_API_KEY

3. Value에는 공공데이터포털 일반 인증키를 붙여넣습니다.
4. 앞뒤에 따옴표를 넣지 않습니다.
5. 인증키가 화면 캡처나 로그에 보이지 않도록 주의합니다.

환경변수 입력란을 찾지 못한 채 먼저 배포했다면 서비스 화면의
`Environment → Add Environment Variable`에서 등록한 뒤 `Save, rebuild, and deploy`를
실행합니다.

4단계: 배포 시작하기

1. `Create Web Service` 또는 `Deploy Web Service`를 누릅니다.
2. 로그 화면에서 설치와 서버 시작이 끝날 때까지 기다립니다.
3. 상태가 `Live`가 되면 화면 위쪽의 `https://...onrender.com` 주소를 누릅니다.

배포 완료 전 로그에 빨간 오류가 뜨면 아래 문제 해결 표를 먼저 확인합니다.

5단계: 배포 결과 확인하기

공개 주소가 `https://example.onrender.com`이라고 가정하면 다음 순서로 확인합니다.

1. `https://example.onrender.com/health`를 엽니다.
2. `ok: true`가 보이면 서버가 켜진 것입니다.
3. 메인 주소 `https://example.onrender.com`을 엽니다.
4. 구·동을 바꾸고 일정이 바뀌는지 확인합니다.
5. `깨진 유리`를 검색합니다.
6. 폐의약품·폐건전지·폐형광등 목록과 지도 마커를 확인합니다.
7. `매트리스`를 검색해 침대 규격별 수수료가 나오는지 확인합니다.
8. 공식 신고 링크가 새 탭에서 열리는지 확인합니다.
9. `내 위치로 지역 찾기`를 누르고 위치 권한을 허용합니다.
10. 구·동과 일정·검색 결과·수거함이 위치 기준으로 갱신되는지 확인합니다.

위치 기능은 HTTPS 공개 주소에서 확인해야 합니다.

자주 생기는 오류

| 화면 또는 로그 | 확인할 것 |
|---|---|
| 서버에 인증키가 설정되지 않았다고 나옴 | 환경변수 이름이 정확히 `DATA_GO_KR_API_KEY`인지 확인하고 재배포 |
| `No module named flask` | Build Command가 `pip install -r requirements-web.txt`인지 확인 |
| `gunicorn` 또는 `web_app`을 찾지 못함 | Start Command와 GitHub 최상단의 `web_app.py` 위치 확인 |
| 메인 화면은 나오지만 지도만 안 나옴 | 브라우저 인터넷 연결과 OpenStreetMap/Leaflet 차단 여부 확인 |
| 위치 권한을 받지 못함 | HTTPS 주소인지 확인하고 브라우저 사이트 권한에서 위치 허용 |
| 첫 접속이 오래 걸림 | Render 무료 서버가 잠들었다가 켜지는 중일 수 있으므로 잠시 기다림 |
| 수정한 코드가 반영되지 않음 | Render에서 최신 커밋으로 Manual Deploy 실행 |

DB 담당자에게 전달할 내용

현재 버전에는 회원가입, 즐겨찾기, 사용자 제보, 운영자 수정처럼 저장할 기능이 없습니다.
일정과 품목 안내는 코드에 있고, 수거함과 수수료는 공공 API에서 읽습니다. 따라서 지금은
DB를 연결하지 않아도 됩니다. 향후 저장 기능을 추가할 때 DB 구조를 설계하면 됩니다.

배포 담당자의 완료 기준

- 공개 HTTPS 주소가 생성됨
- `/health`가 `ok: true`
- 인증키 오류 없이 수거함·수수료 조회 가능
- 위치 권한 허용 후 지역과 정보가 갱신됨
- 공개 주소를 다른 휴대폰이나 PC에서도 열 수 있음

완료 후 공개 주소와 배포일을 팀 채팅에 공유합니다. 인증키는 공유하지 않습니다.
